# API Documentation

Full interactive, always-up-to-date API documentation is auto-generated by
FastAPI from the route definitions and Pydantic schemas:

- Swagger UI: `/api/docs`
- ReDoc: `/api/redoc`
- Raw OpenAPI schema: `/api/openapi.json`

This document describes the conventions that apply across every endpoint,
plus a map of the modules — it is not a substitute for the generated docs.

## Conventions

- **Base path**: all endpoints are under `/api/v1`.
- **Auth**: Bearer JWT in the `Authorization` header, except `POST
  /api/v1/auth/login` and `POST /api/v1/auth/refresh`. Obtain a token pair
  via login; access tokens expire in 30 minutes (`ACCESS_TOKEN_EXPIRE_MINUTES`),
  refresh tokens in 7 days (`REFRESH_TOKEN_EXPIRE_DAYS`) and rotate on use.
- **Pagination**: list endpoints accept `page` (default 1), `page_size`
  (default 20, max 100), `search`, `sort_by`, `sort_order` (`asc`/`desc`) and
  return `{ items, total, page, page_size, total_pages }`.
- **Errors**: every error response is `{ error_code, message, details?,
  request_id? }`. `error_code` is a stable machine-readable string (e.g.
  `NOT_FOUND`, `VALIDATION_ERROR`, `FORBIDDEN`) — see
  `backend/app/exceptions/base.py` for the full set and their HTTP status
  codes.
- **Soft delete**: `DELETE` endpoints soft-delete (set `is_deleted`/
  `deleted_at`); deleted records are excluded from `GET`/list results by
  default.
- **Rate limiting**: `POST /api/v1/auth/login` is limited to 5/minute per IP
  (`RATE_LIMIT_LOGIN`); all other endpoints default to 100/minute
  (`RATE_LIMIT_DEFAULT`). A `429` response body follows the same error
  shape (`RATE_LIMIT_EXCEEDED`).
- **Permissions**: every non-auth endpoint requires a specific permission
  code (see `backend/app/permissions/permission_codes.py`); Super Admin
  bypasses all checks. A missing permission returns `403 FORBIDDEN`.

| Module | Prefix | Notes |
|---|---|---|
| Authentication | `/auth` | login, refresh, logout, logout-all, change-password, me |
| User Management | `/users` | staff/system accounts |
| Role Management | `/roles` | permission bundles |
| Permission Management | `/permissions` | the permission registry |
| Audit Logs | `/audit-logs` | read-only, immutable trail |
| Dashboard | `/dashboard` | aggregate overview stats |
| Lead Management (CRM) | `/leads` | pre-sales pipeline, includes `/assign` |
| Admissions | `/admissions` | confirms a Student into a Course/Batch |

| Course Management | `/courses` | |
| Batch Management | `/batches` | |
| Tutor Management | `/tutors` | |

## Example: Login → Authenticated Request

```bash
# 1. Log in
curl -X POST http://localhost:8000/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"admin@hrnavinos.com","password":"ChangeMe123!"}'
# => { "access_token": "...", "refresh_token": "...", "token_type": "bearer", "expires_in": 1800 }

# 2. Call a protected endpoint
curl http://localhost:8000/api/v1/dashboard/overview \
  -H "Authorization: Bearer <access_token>"
```
